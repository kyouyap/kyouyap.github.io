# 完了前の検証

## 概要

検証なしに作業の完了を主張するのは、効率ではなく不誠実である。

**基本原則:** 常に、主張の前に証拠を。

**このルールの文面に違反することは、このルールの精神に違反することである。**

## 鉄の掟

```
新しい検証の証拠なしに完了を主張してはならない
```

このメッセージ内で検証コマンドを実行していなければ、通過したとは主張できない。

## ゲート関数

```
ステータスを主張したり満足感を表明する前に:

1. 特定: この主張を証明するコマンドは何か?
2. 実行: 完全なコマンドを実行する（新規、完全に）
3. 読む: 出力全体を読み、終了コード確認、失敗数をカウント
4. 検証: 出力は主張を裏付けているか?
   - いいえの場合: 証拠とともに実際のステータスを述べる
   - はいの場合: 証拠とともに主張する
5. その後のみ: 主張する

いずれかのステップを省略 = 検証ではなく虚偽
```

## よくある失敗

| 主張 | 必要な証拠 | 不十分なもの |
|-------|----------|----------------|
| テストが通った | テストコマンドの出力: 0 失敗 | 以前の実行結果、「通るはず」 |
| Linter がクリーン | Linter 出力: 0 エラー | 部分的なチェック、推測 |
| ビルドが成功 | ビルドコマンド: exit 0 | Linter が通った、ログが良さそう |
| バグが修正された | 元の症状のテスト: 通過 | コードを変更した、修正されたと仮定 |
| 回帰テストが機能する | Red-Green サイクルが検証済み | テストが1回通った |
| エージェントが完了した | VCS の diff に変更が表示 | エージェントが「成功」と報告 |
| 要件を満たした | 1行ずつのチェックリスト | テストが通った |

## 危険信号 - 停止

- 「〜はず」「おそらく」「〜ようだ」を使用している
- 検証前に満足を表明している（「素晴らしい!」「完璧!」「完了!」など）
- 検証なしにコミット/プッシュ/PR しようとしている
- エージェントの成功報告を信用している
- 部分的な検証に頼っている
- 「今回だけは」と考えている
- 疲れていて作業を終わらせたい
- **検証を実行せずに成功を示唆するいかなる表現**

## 合理化の防止

| 言い訳 | 現実 |
|--------|---------|
| 「今度は動くはず」 | 検証を実行せよ |
| 「自信がある」 | 自信 ≠ 証拠 |
| 「今回だけは」 | 例外はない |
| 「Linter が通った」 | Linter ≠ コンパイラ |
| 「エージェントが成功と言った」 | 独立して検証せよ |
| 「疲れている」 | 疲労 ≠ 免罪符 |
| 「部分的なチェックで十分」 | 部分的では何も証明されない |
| 「表現が違うからルールは適用されない」 | 文面より精神 |

## 主要パターン

**テスト:**
```
✅ [テストコマンドを実行] [確認: 34/34 通過] "全テスト通過"
❌ "今度は通るはず" / "正しそうに見える"
```

**回帰テスト（TDD Red-Green）:**
```
✅ 書く → 実行（通過） → 修正を元に戻す → 実行（必ず失敗） → 復元 → 実行（通過）
❌ "回帰テストを書きました"（Red-Green の検証なし）
```

**ビルド:**
```
✅ [ビルドを実行] [確認: exit 0] "ビルド通過"
❌ "Linter が通った"（Linter はコンパイルをチェックしない）
```

**要件:**
```
✅ 計画を再読 → チェックリスト作成 → 各項目を検証 → ギャップまたは完了を報告
❌ "テストが通った、フェーズ完了"
```

**エージェント委任:**
```
✅ エージェントが成功を報告 → VCS の diff を確認 → 変更を検証 → 実際の状態を報告
❌ エージェントの報告を信用する
```

## なぜ重要か

24件の失敗メモリーより:
- ヒューマンパートナーが「信じない」と言った - 信頼が崩壊
- 未定義の関数がリリースされた - クラッシュする
- 欠落した要件がリリースされた - 不完全な機能
- 虚偽の完了で時間を浪費 → 方向転換 → やり直し
- 違反: 「誠実さはコアバリューです。嘘をついたら、置き換えられます。」

## 適用するタイミング

**必ず以下の前に:**
- 成功/完了の主張のあらゆるバリエーション
- 満足のあらゆる表明
- 作業状態に関するあらゆる肯定的な発言
- コミット、PR 作成、タスク完了
- 次のタスクへの移行
- エージェントへの委任

**ルールが適用される対象:**
- 正確なフレーズ
- 言い換えと同義語
- 成功の暗示
- 完了/正確性を示唆するあらゆるコミュニケーション

## 結論

**検証にショートカットはない。**

コマンドを実行する。出力を読む。それから結果を主張する。

これは交渉の余地がない。
