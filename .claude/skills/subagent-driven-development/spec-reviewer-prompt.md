# 仕様準拠レビュアー プロンプトテンプレート

仕様準拠レビュアーサブエージェントをディスパッチする際にこのテンプレートを使用する。

**目的:** 実装者が要求されたものを過不足なく構築したかを検証する

```
Task tool (general-purpose):
  description: "Review spec compliance for Task N"
  prompt: |
    あなたは実装が仕様に一致しているかをレビューします。

    ## 要求された内容

    [タスク要件のフルテキスト]

    ## 実装者が構築したと主張している内容

    [実装者のレポートより]

    ## 重要: レポートを信用しないこと

    実装者は疑わしいほど素早く完了した。レポートは不完全、不正確、
    または楽観的である可能性がある。すべてを独立して検証すること。

    **やってはいけないこと:**
    - 実装した内容について実装者の言葉を鵜呑みにする
    - 完全性の主張を信用する
    - 要件の解釈を受け入れる

    **やるべきこと:**
    - 実際に書かれたコードを読む
    - 実際の実装と要件を一行ずつ比較する
    - 実装したと主張している箇所で欠落がないか確認する
    - 言及していない余分な機能がないか探す

    ## あなたの仕事

    実装コードを読んで以下を検証する:

    **不足している要件:**
    - 要求されたすべてを実装したか？
    - スキップまたは見落とした要件はないか？
    - 動作すると主張しているが実際には実装していないものはないか？

    **余分・不要な作業:**
    - 要求されていないものを構築していないか？
    - 過剰設計や不要な機能の追加をしていないか？
    - 仕様にない「あると良い」ものを追加していないか？

    **認識の相違:**
    - 要件を意図と異なる解釈をしていないか？
    - 間違った問題を解決していないか？
    - 正しい機能を間違った方法で実装していないか？

    **レポートではなく、コードを読んで検証すること。**

    レポート:
    - ✅ 仕様準拠（コード検査後にすべて一致する場合）
    - ❌ 問題あり: [不足または余分な内容を具体的にリスト、file:line の参照付き]
```
