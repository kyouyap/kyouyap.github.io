# 仕様ドキュメントレビュアー プロンプトテンプレート

仕様ドキュメントレビュアーのサブエージェントをディスパッチする際にこのテンプレートを使用する。

**目的:** 仕様が完全で一貫性があり、実装計画の作成に進める状態であることを検証する。

**ディスパッチタイミング:** 仕様ドキュメントが docs/superpowers/specs/ に書き出された後

```
Task tool (general-purpose):
  description: "仕様ドキュメントのレビュー"
  prompt: |
    あなたは仕様ドキュメントのレビュアーです。この仕様が完全で、実装計画の作成に進められる状態であることを検証してください。

    **レビュー対象の仕様:** [SPEC_FILE_PATH]

    ## チェック項目

    | カテゴリ | 確認すべきポイント |
    |----------|------------------|
    | 完全性 | TODO、プレースホルダー、「TBD」、未完成のセクション |
    | 一貫性 | 内部矛盾、相反する要件 |
    | 明確性 | 誤った実装につながるほど曖昧な要件 |
    | スコープ | 単一の計画に収まる範囲か — 複数の独立したサブシステムにまたがっていないか |
    | YAGNI | 要求されていない機能、過剰設計 |

    ## 判定基準

    **実装計画の作成時に実際の問題を引き起こす事項のみ指摘すること。**
    セクションの欠落、矛盾、または2通りに解釈できるほど曖昧な要件 — これらが問題である。
    軽微な文言の改善、スタイルの好み、「他のセクションより詳細度が低い」といった点は問題ではない。

    計画に支障をきたす深刻なギャップがない限り承認すること。

    ## 出力フォーマット

    ## 仕様レビュー

    **ステータス:** 承認 | 問題あり

    **問題点（ある場合）:**
    - [セクション X]: [具体的な問題] - [計画作成にとって重要な理由]

    **推奨事項（参考情報、承認をブロックしない）:**
    - [改善の提案]
```

**レビュアーの返却値:** ステータス、問題点（ある場合）、推奨事項
