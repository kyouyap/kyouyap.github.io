# 計画の実行

## 概要

計画を読み込み、批判的にレビューし、すべてのタスクを実行し、完了したら報告する。

**開始時の宣言:** "executing-plans スキルを使用してこの計画を実装します。"

**注意:** Superpowers はサブエージェントにアクセスできる方が遥かに効果的に動作することをヒューマンパートナーに伝えてください。サブエージェントをサポートするプラットフォーム（Claude Code や Codex など）で実行すると、作業品質が大幅に向上します。サブエージェントが利用可能な場合は、このスキルの代わりに subagent-driven-development を使用してください。

## プロセス

### Step 1: 計画の読み込みとレビュー

1. 計画ファイルを読む
2. 批判的にレビューする — 計画に関する質問や懸念を特定する
3. 懸念がある場合: 開始前にヒューマンパートナーに相談する
4. 懸念がない場合: TodoWrite を作成して進める

### Step 2: タスクの実行

各タスクについて:

1. in_progress にマークする
2. 各ステップを正確に実行する（計画には細分化されたステップがある）
3. 指定された検証を実行する
4. completed にマークする

### Step 3: 開発の完了

すべてのタスクが完了し検証された後:

- 宣言する: "finishing-a-development-branch スキルを使用してこの作業を完了します。"
- **必須サブスキル:** finishing-a-development-branch を使用する
- そのスキルに従い、テスト検証、選択肢の提示、選択の実行を行う

## 作業を中断してヘルプを求めるタイミング

**以下の場合は直ちに実行を停止する:**

- ブロッカーに遭遇した（依存関係の欠如、テスト失敗、指示が不明瞭）
- 計画に開始を妨げる重大な欠陥がある
- 指示が理解できない
- 検証が繰り返し失敗する

**推測するのではなく、明確化を求めること。**

## 以前のステップに戻るタイミング

**レビュー（Step 1）に戻る場合:**

- パートナーがフィードバックに基づいて計画を更新した
- 根本的なアプローチの再考が必要

**ブロッカーを無理に突破しない** - 止まって相談すること。

## 覚えておくこと

- まず計画を批判的にレビューする
- 計画のステップを正確に実行する
- 検証をスキップしない
- 計画で指定されたスキルを参照する
- ブロックされたら止まる、推測しない
- ユーザーの明示的な同意なしに main/master ブランチで実装を開始しない

## 連携

**必要なワークフロースキル:**

- **using-git-worktrees** - 必須: 開始前に隔離されたワークスペースをセットアップする
- **writing-plans** - このスキルが実行する計画を作成する
- **finishing-a-development-branch** - すべてのタスク完了後に開発を完了する
