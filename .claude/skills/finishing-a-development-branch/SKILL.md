# 開発ブランチの完了

## 概要

明確な選択肢を提示し、選択されたワークフローを処理することで、開発作業の完了を導く。

**基本原則:** テスト検証 → 選択肢の提示 → 選択の実行 → クリーンアップ。

**開始時の宣言:** "finishing-a-development-branch スキルを使用してこの作業を完了します。"

## プロセス

### Step 1: テストの検証

**選択肢を提示する前に、テストが通ることを確認する:**

```bash
# プロジェクトのテストスイートを実行
npm test / cargo test / pytest / go test ./...
```

**テストが失敗した場合:**
```
テストが失敗しています（<N> 件の失敗）。完了前に修正が必要です:

[失敗を表示]

テストが通るまでマージ/PRに進めません。
```

停止する。Step 2 に進まない。

**テストが通った場合:** Step 2 に進む。

### Step 2: ベースブランチの確認

```bash
# 一般的なベースブランチを試す
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

または確認する: "このブランチは main から分岐しています — 正しいですか?"

### Step 3: 選択肢の提示

以下の4つの選択肢を正確に提示する:

```
実装が完了しました。どうしますか?

1. <base-branch> にローカルでマージ
2. プッシュして Pull Request を作成
3. ブランチをそのまま保持（後で対応する）
4. この作業を破棄する

どの選択肢にしますか?
```

**説明を追加しない** - 選択肢は簡潔に。

### Step 4: 選択の実行

#### 選択肢 1: ローカルマージ

```bash
# ベースブランチに切り替え
git checkout <base-branch>

# 最新を取得
git pull

# フィーチャーブランチをマージ
git merge <feature-branch>

# マージ結果でテストを検証
<test command>

# テストが通ったら
git branch -d <feature-branch>
```

次に: worktree のクリーンアップ（Step 5）

#### 選択肢 2: プッシュして PR を作成

```bash
# ブランチをプッシュ
git push -u origin <feature-branch>

# PR を作成
gh pr create --title "<title>" --body "$(cat <<'EOF'
## Summary
<変更内容の2-3箇条書き>

## Test Plan
- [ ] <検証手順>
EOF
)"
```

次に: worktree のクリーンアップ（Step 5）

#### 選択肢 3: そのまま保持

報告する: "ブランチ <name> を保持します。worktree は <path> に保持されます。"

**worktree をクリーンアップしない。**

#### 選択肢 4: 破棄

**まず確認する:**
```
以下が永久に削除されます:
- ブランチ <name>
- すべてのコミット: <commit-list>
- worktree: <path>

確認するには 'discard' と入力してください。
```

正確な確認を待つ。

確認された場合:
```bash
git checkout <base-branch>
git branch -D <feature-branch>
```

次に: worktree のクリーンアップ（Step 5）

### Step 5: worktree のクリーンアップ

**選択肢 1, 2, 4 の場合:**

worktree 内かどうかを確認する:
```bash
git worktree list | grep $(git branch --show-current)
```

該当する場合:
```bash
git worktree remove <worktree-path>
```

**選択肢 3 の場合:** worktree を保持する。

## クイックリファレンス

| 選択肢 | マージ | プッシュ | worktree 保持 | ブランチ削除 |
|--------|-------|------|---------------|----------------|
| 1. ローカルマージ | ✓ | - | - | ✓ |
| 2. PR 作成 | - | ✓ | ✓ | - |
| 3. そのまま保持 | - | - | ✓ | - |
| 4. 破棄 | - | - | - | ✓ (強制) |

## よくある間違い

**テスト検証のスキップ**
- **問題:** 壊れたコードをマージ、失敗する PR を作成
- **対策:** 選択肢を提示する前に必ずテストを検証する

**オープンエンドな質問**
- **問題:** "次はどうしましょう?" → 曖昧
- **対策:** 正確に4つの構造化された選択肢を提示する

**自動的な worktree クリーンアップ**
- **問題:** 必要かもしれない worktree を削除（選択肢 2, 3）
- **対策:** 選択肢 1 と 4 の場合のみクリーンアップする

**破棄時の確認なし**
- **問題:** 誤って作業を削除
- **対策:** "discard" の入力確認を要求する

## 危険信号

**絶対にしないこと:**
- テストが失敗した状態で進める
- マージ結果のテスト検証なしにマージする
- 確認なしに作業を削除する
- 明示的な要求なしに force-push する

**必ず行うこと:**
- 選択肢を提示する前にテストを検証する
- 正確に4つの選択肢を提示する
- 選択肢 4 では入力確認を取得する
- 選択肢 1 と 4 の場合のみ worktree をクリーンアップする
