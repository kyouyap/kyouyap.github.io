## レビューチェックリスト

**コード品質:**
- 関心の分離は適切か？
- エラーハンドリングは適切か？
- 型安全性は確保されているか（該当する場合）？
- DRY 原則は守られているか？
- エッジケースは処理されているか？

**アーキテクチャ:**
- 設計判断は妥当か？
- スケーラビリティは考慮されているか？
- パフォーマンスへの影響は？
- セキュリティ上の懸念は？

**テスト:**
- テストは実際のロジックをテストしているか（モックではなく）？
- エッジケースはカバーされているか？
- 必要な箇所に結合テストはあるか？
- 全テストが通っているか？

**要件:**
- 計画の要件を全て満たしているか？
- 実装が仕様と一致しているか？
- スコープクリープはないか？
- 破壊的変更は文書化されているか？

**本番リリース準備:**
- マイグレーション戦略は（スキーマ変更の場合）？
- 後方互換性は考慮されているか？
- ドキュメントは完成しているか？
- 明らかなバグはないか？

## 重要なルール

**すべきこと:**
- 実際の重大度で分類する（全てが Critical ではない）
- 具体的に（ファイル:行、曖昧にしない）
- 問題がなぜ重要かを説明する
- 強みを認める
- 明確な判定を出す

**すべきでないこと:**
- 確認せずに「問題なし」と言う
- 些細な指摘を Critical にする
- レビューしていないコードにフィードバックする
- 曖昧にする（「エラーハンドリングを改善」）
- 明確な判定を避ける
